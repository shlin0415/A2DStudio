# A2D 项目包 v2 设计说明

日期：2026-10-22
状态：方案已由用户确认按推荐方向推进；本文作为实现依据
范围：A2D Studio 项目导出与导入的 ZIP 格式

## 1. 背景与当前实现

当前前端项目包位于 `frontend_vue/src/composables/useA2DProject.ts`。现有格式使用 ZIP v1，将项目导出信封（`ExportEnvelope`）写入 `project.json`，并将台词音频复制到 `assets/audio/`。背景、图片叠层、BGM、GSV 参考音频等路径字段仍可能指向本机文件；导入端主要检查台词 WAV 路径，并通过 `fflate` 一次性解压 ZIP。

项目数据还混合了便携内容和本机运行状态：`ScriptLine`、`LineOverlay` 会引用本机路径或角色 ID；`GameRole` 带有 `roleId`、`character_folder` 等运行时身份；`gsv_params` 是开放字典。直接复制现有 envelope 会把机器相关信息带进包中，或导入后保留无法解析的路径。

本次先明确 v2 的边界和验证条件，不在本阶段修改导入、导出代码。

## 2. 目标

1. 生成一个可在另一台 A2D Studio 安装中打开的自包含 ZIP：已生成台词音频和项目明确引用的视觉、音乐及参考音频素材随包保存。
2. 项目内容只携带稳定的项目角色键，不依赖导出机器的 `GameRole.roleId`、角色目录名或本地角色配置。
3. 导入时验证格式、资源路径、资源存在性和包体限制；不读取包外路径或远程 URL。
4. 让已有台词音频和舞台素材可播放；重新合成则使用导入机器本地配置的 GSV 服务与角色绑定。
5. 明确排除密钥、端点、本机设置、模型权重、数据库、日志和未引用资源。

## 3. 非目标

- 不做 v1 导入兼容；v2 是唯一支持的项目 ZIP 格式。旧包需要由旧版本打开并重新导出，或者之后按独立迁移工具需求处理。
- 不随项目包携带 GSV、LLM 或其他模型权重、可执行程序、环境配置或服务端点。
- 不把整个角色库、全局应用动画、气泡/特效素材或未被项目引用的文件打进 ZIP。
- 不保证导入后无需本机配置即可重新合成语音。
- 不改变项目工作流、舞台播放逻辑或音频生成策略。

## 4. v2 包结构

```text
<project-name>.a2d.zip
├── project.json
└── assets/
    ├── audio/          # 已生成的台词音频
    ├── backgrounds/    # 项目明确引用的背景
    ├── images/         # 图片叠层等项目素材
    ├── music/          # 项目明确引用的 BGM
    ├── references/     # 被使用角色绑定的 GSV 参考音频
    └── avatars/        # 项目使用的角色/表情/服装头像
```

未使用的目录不必写入 ZIP。资源路径由包内相对路径组成，统一使用 `/` 分隔，路径须保持在 `assets/` 下。资源文件名由导出器生成确定性、安全的相对路径；不得保留本机原始绝对路径作为包路径。

## 5. `project.json` 数据边界

`project.json` 使用显式的 A2D 项目 schema，而不是直接序列化完整 `ExportEnvelope`。至少包括：

- 格式标识、`schema_version: 2`、项目元数据；
- 项目角色表：稳定的项目角色键（例如 `role_1`）、显示名及项目确实需要的呈现信息；
- 台词、舞台/阶段、播放设置、项目级视觉与音乐设置；
- 每个已打包资源的相对路径、媒体类别和必要的 MIME/文件大小元数据；
- 台词 WAV 资源及被项目实际使用的舞台资源引用。

不得序列化或保留 `GameRole.roleId`、`character_folder`、本机用户数据根目录、GSV/LLM 地址、API key、环境变量、服务配置或不属于项目格式的运行时字段。`gsv_params` 只能写入经过字段白名单定义、且确属项目内容的参数；不得把开放字典原样复制到包内。项目角色键在同一包内必须唯一，所有台词 speaker 和角色绑定必须能解析到项目角色或明确的空角色状态。

字段名与完整 schema 在实现计划阶段依据当前正式数据模型确定；此处列出数据边界与不变量，不虚构尚未核对的字段。

## 6. 资源收集规则

导出器从项目的显式引用中收集去重后的资源，并将其复制到包内：

- 每条已有的台词音频；
- 项目设置和各阶段明确引用的背景；
- 项目使用的图片叠层；
- 项目明确引用的 BGM；
- 当前项目角色绑定且实际用于 GSV 合成的参考 WAV；
- 项目用到的角色/表情/服装头像文件。

只有显式引用的素材才能进入包。应用随安装提供的气泡、动作动画、通用效果等资产属于应用资源，不进入项目包。多个字段引用同一个源文件时，包中只存一份并复用同一个相对路径。

若任一非空引用缺失、不可读、媒体类别不符，导出必须失败并指出具体项目字段；不得悄悄丢弃资源、改用其他资源或留下原路径。空字段按 schema 定义保留为空。

## 7. 路径与导入安全

导入器仅接受规范的包内相对资源路径，并拒绝：绝对路径、盘符路径、UNC 路径、URL、路径穿越（`..`）、反斜线变体、重复/冲突的归一化路径，以及未在资源清单中声明的资源引用。解包目标必须位于新建的隔离临时目录内，完成所有验证后才作为项目数据交给应用。

ZIP 解包必须按流式/分块方式统计实际解压字节数，不只信任 ZIP 中声明的大小；检测超限、截断、CRC 错误、重复条目或压缩炸弹时立即拒绝。失败时不得留下部分导入项目。ZIP 中的条目名须先规范化再检查，防止不同分隔符或编码形式绕过路径验证。

导入文件类型由用途白名单确定：WAV 用于语音与 GSV 参考音频；背景、图片叠层、BGM、头像采用项目当前真实支持的媒体格式。实现阶段需从现有前端、后端和模型调用确认媒体白名单，不凭扩展名单独信任内容。

## 8. 包体限制

v2 首版上限：

| 限制 | 上限 |
| --- | ---: |
| ZIP 文件大小 | 512 MiB |
| 单个解压后条目 | 128 MiB |
| 全部条目解压后合计 | 512 MiB |
| ZIP 条目数 | 1,024 |
| `project.json` 大小 | 10 MiB |

实现必须在读取或解压过程中执行限制，不能在完整解压到内存后才检查。超限时报清楚是哪项限制被触发，并让导入保持无部分结果。若这些上限与项目真实素材需求冲突，先收集实际项目包体样本再调整上限，不静默截断。

## 9. 角色与重新合成边界

导入后的项目角色使用包内稳定键；应用通过用户在本机可用的角色/GSV 配置完成本地合成绑定。项目包可以保存当前使用角色的参考 WAV 和已生成语音，因此即使目标机器没有相同角色配置，项目仍可播放已有语音与舞台素材。

若本地缺少适用于重新合成的 GSV 配置，重新合成操作应明确提示本机需要配置对应角色与服务；不得从项目包加载端点、密钥或模型，也不得静默切换角色/服务。项目内的角色选择与本机绑定关系应在运行时显式维护，保存项目时不把本机身份写回便携 schema。

## 10. 版本规则

- `schema_version` 必须严格等于 `2`；不认识的版本或格式标识应明确拒绝。
- v2 不猜测、修复或回退不合规数据；错误需包含 JSON 字段路径或 ZIP 条目名。
- 任何未来不兼容 schema 变化使用新的版本号，并另行设计迁移策略。
- v2 不能包含 v1 envelope 的隐式兼容层。

## 11. 验收条件

1. 导出包只包含项目明确引用的素材；包内没有本机绝对路径、密钥、服务端点、模型、数据库或日志。
2. 在另一套干净用户数据目录中导入后，台词、已有语音、背景、图片叠层、BGM、角色头像与阶段播放引用均能解析到 ZIP 内资源。
3. 能通过已有台词音频播放项目；重新合成所需的本机角色/GSV 绑定缺失时给出可操作的明确错误。
4. 缺失引用、越界路径、恶意 ZIP 条目、格式错误、CRC/截断错误和每种包体超限均被拒绝，且不会生成半成品项目。
5. ZIP 中重复引用的同一素材只存一份；未使用素材不会被收集。
6. 不接受 v1 或未知 schema 版本。
7. 单元测试覆盖 schema 合法性、引用闭合、路径边界、资源收集、容量限制、损坏 ZIP 拒绝和导入失败原子性；后续实现计划需包含最短本地验证路径。

## 12. 实现拆分（待设计审阅后再规划）

1. 固定 v2 schema 与资源引用映射，逐项对照 `ScriptLine`、`LineOverlay`、阶段与角色配置。
2. 实现导出：白名单序列化、资源解析与去重、ZIP 资源清单、缺失引用错误。
3. 实现导入：格式/路径/媒体验证、受限流式解包、隔离目录和原子交接。
4. 接通导入后的本机角色/GSV 绑定提示及已有音频播放。
5. 按验收条件增加测试，再运行最短验证路径与前端构建检查。

用户已确认按推荐的 v2 方向推进；开始实现前仍需在实现计划中对照当前数据模型，遇到与本设计冲突的现状时先报告，不擅自扩大兼容范围。
